What changes

Six pages to read, or one screen to click.

Written spec as the decision artifact
  • Read by each reviewer separately, interpreted differently
  • Layout questions argued in words ("three panels at 1280px?")
  • Acceptance criteria checked after engineering builds
  • The decision lives in meeting notes
Prototype plus one-page brief
  • Clicked by everyone in the same review
  • Layout questions answered by resizing the window
  • Acceptance criteria run by the prototype on itself before the review
  • The decision is written into the brief, section 8
How a PM ships one

Five steps, one owner each.

  • 1Write the briefPMOne page: the decision the prototype settles, who uses it, what it does, five to eight acceptance checks.
  • 2Run the Prototypes project in GreenlightPM, in GreenlightAttach the brief (or an existing PRD) and type "Build the prototype". Greenlight returns one working HTML file on the Intradiem design system; save it as index.html.
  • 3Self-checkPMPress Checks (or ?) in the prototype. Computable checks show pass or fail; the rest are marked manual. A fail goes back to Greenlight in one sentence and the whole file comes back fixed.
  • 4Review on the prototypePM, design, engineeringThe room clicks through. Answers to the brief's open questions go into the decision record.
  • 5Hand offPM to engineeringPrototype plus brief. A PRD is written afterwards only where a compliance or contract record requires one.

Worked example

One PRD, rendered as it reads.

The Skills Editor PRD specifies a 256px sidebar, a three-panel editor (roster, dimension tabs, Compare to Template), a save-confirm workflow, and eight acceptance criteria. The prototype implements all of it in one file with no external requests, and tests the criteria on itself.

Live prototype. Click an agent, switch the Process / Case / Business Object tabs, press ? for the checks.Open full screen →
  • AC-01DS colours: sidebar #F8F8F8, primary buttons #5AB274, active tab underline, no #014637 or #2DB56E in chromecomputed
  • AC-02No emoji in chrome; nav icons are inline SVGcomputed
  • AC-03Business Object tab renders System Objects and insurance classes with counts above zerocomputed
  • AC-04Compare to Template shows all four categories for Sarah Chen; Missing includes Part-D and Medicaidcomputed
  • AC-05Process activity column never shows "undefined"computed
  • AC-06Save persists: reselecting the agent shows the updated levelscomputed
  • AC-07Three panels reflow at 1280px; no horizontal overflow at 1080px and abovecomputed
  • AC-08Primary buttons 36px, 4px radius, 700 14px, letter-spacing .03emcomputed

Result on Aug 31 2026: one file of 78 KB, no external requests, all eight checks computed by the prototype and passing at 1440px and 1080px. Sarah Chen's Compare to Template shows 20 met, 4 below, 2 missing (Medicaid, Part-D), 4 extra. Build time from PRD to passing checks: about seven minutes of agent run, plus the brief. Open Sans and Roboto are declared but not embedded, so a machine without them shows the system font.

What a review on this prototype would settle

The PRD leaves three questions open, and they are the ones a room answers by clicking: whether Compare to Template belongs beside the editor or as a step before Save; whether the right panel dropping under the centre at 1280px is acceptable on laptops; whether Quick Add inserts at level 1 or asks for a level. No review has been held; the example brief records them as open.

Worked example, second PRD

One screen of a 37-page PRD, built from the project alone.

The Scheduling Service PRD covers 22 screens and 158 requirements. Screen 7, the holiday calendar, was built with nothing but the Greenlight project instructions, the token sheet and the PRD: a three-tier country, region, site hierarchy with inheritance and overrides, pre-loaded 2026 public holidays for five countries, floating-date recurrence into 2027, calendar and list views, and an impact preview before any change commits.

Live prototype. Pick a site in the scope tree, switch Calendar and List, add a non-working day, press Checks for the panel.Open full screen →

  • AC-22026 public holidays pre-loaded for every country; recurring days regenerate on the correct 2027 dates, floating and observedcomputed
  • AC-3A day added at any tier is still there after switching scope and backcomputed
  • AC-4Calendar colour-codes by tier; list sorts by date, name and tiercomputed
  • AC-5Impact (agents, intervals) shows before add or remove; nothing changes until confirmedcomputed
  • AC-6Chrome follows the token sheet: 36px buttons, 4px radius, 256px sidebar, 48px rows, token colours onlycomputed
  • AC-7No horizontal overflow at 1440 and 1920, no broken value text, every control boundcomputed
  • AC-8The add flow completes with the keyboard onlymanual

Result on Sep 1 2026: one file of 59 KB, no external requests. The self-check caught one token deviation on the first pass (checkbox text falling back to browser black); one sentence back to Greenlight in the PM's words returned the whole file with a one-line fix. Seven checks computed and passing at 1920 and 1440, one manual. The brief was drafted from the PRD in the same run, with the PRD's eight unsettled questions listed for the review.

What a review on this prototype would settle

Whether a site can restore a day its region marked as worked, or only the tier that set the override; whether "intervals affected" counts rostered agents or headcount; and which design system Screen 7 belongs to, since the PRD names one and the token sheet another. No review has been held; the brief records them as open.
