The goal of the GTM engine's Claude/language layer is NOT that Dallas produces the writing for Nate and the team. It is that Dallas builds tools (skills) the team invokes themselves.

**Why:** If Naveen or anyone walks away thinking "this is nice but it only works if Dallas is doing it," the engine reads as a personal workflow, not a function. The value story is leverage: Dallas maintains the tools and the claims file; the team drafts, handles objections, and preps with those tools directly. "If I'm out for a week, the engine doesn't slow down."

**How to apply:** In every engine-facing doc, deck, or talking point ([[contacts-table-finalized-jul9]] docs, launch kits, Norton materials, readouts), frame the Claude layer as "skills that run the same for whoever invokes them," "tools in your hands, not requests you file with Dallas," and Dallas's role as "keeping the tools sharp and the claims file current, not ghostwriting sends." Check any sentence like "the writing lives in Claude" for the ambiguous reading that it lives with Dallas, and disambiguate. Applied to both Clay engine HTMLs Jul 9 2026.
