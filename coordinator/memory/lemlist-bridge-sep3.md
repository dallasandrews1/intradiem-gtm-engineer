Clay workflow CLI lessons (cost a dozen rebuild loops): node create takes the FLAT schema form `{name:{type,description,sourceNodeId,sourcePath}}` for inputSchema and outputSchema (full JSON-schema form is rejected on create, accepted on update); every flat input becomes required, so relax `required` by update when a trigger field can be absent (a missing sourcePath fails the node); conditional rule edges are declared on the TARGET node's `incomingEdges` as `{sourceNode, ruleId, ruleName}` and the default route as `{sourceNode, isDefaultRoute:true}`; the HTTP API action (`http-api-v2`) drops static `Authorization` headers (object static rejected on create, JSON-string and pipe-notation silently ignored, reference must be an object which code nodes cannot output) so put basic-auth credentials in the URL (`https://:KEY@api.lemlist.com/...`), which the action honors; code nodes: outputs are scalars only, no `datetime` module; `clay workflows actions test` runs an action once (Audiences upserts refuse it, they only run inside a workflow); `workflows runs test --audience-segment <seg> --limit 1` executes for real; new workflows are not visible to `clay routines` immediately. lemlist: POST /api/contacts rejects unknown keys (custom fields are UI-created), lists via POST /api/contacts/lists/{id}/entities {"action":"add","contactIds":[...]}.

**How to apply:** any new motion = add the list to `lemlist_bridge_config.json`, rebuild, queue people by stamping Push Motion. Reuse the lessons block for every Clay workflow build. Related: [[bo-netnew-package-sep2]], [[carter-webinar-lead-engine-aug20]], [[clay-cli-upgraded-aug26]].
