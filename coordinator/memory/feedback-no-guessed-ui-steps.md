On Aug 25 2026 Dallas opened Clay's Website visitor tracking setup and the first screen was a table-configuration choice (one row per company vs new row per visit). My sheet, written from a summarized read of university.clay.com/docs/website-tracking, started at Settings -> Website tracking and never mentioned that screen. He said: "stop guessing what the steps are and the current processes."

**Why:** a wrong first step costs him the whole sheet's credibility and his time in the UI. Clay ships UI ahead of its docs; a summarized doc read is a guess dressed as a verified step.

**How to apply:** for any UI sheet, fetch the docs verbatim (not summarized) and state the doc date or version; where the docs are silent, write "the docs stop here" and ask Dallas for the screen (a downscaled screenshot or the field list) instead of inventing labels; decide each screen's choice from what our build needs and say the reason. The CLI has no view of website-tracking connections, so nothing about that flow can be verified headlessly. Related: [[signal-marketing-loop-strategy-aug25]], [[feedback-direct-task-callouts]].
