Jul 20 2026: Rebuilding the Stars 5-touch workflow `wf_0tiegzuo3PzJ4UtUGFA` to actually COMPLETE runs (it validated clean but every real/CLI run failed). These are Clay Terracotta RUNTIME rules that `validate_workflow` does NOT catch — the only way to find them is `clay workflows runs test <wf> --input -` then `runs steps` to see which node failed. `runs get`/`runs steps` per-node status is the debugger.

**1. Agent nodes MUST set `automapInputs: false`.** With the default (true), an agent node runs an async input-inference pass that HANGS/fails silently (status failed, isAsync=true, empty output, no error). This was THE single blocker on the inline figure critic. The working Voice Audit agent had automapInputs=false; copying that fixed it. Always set automapInputs=false on agent nodes and pin every input with explicit sourceNodeId/sourcePath.

**2. A CODE node reading an AGENT node's output must use path `$.structuredOutputs.<field>`, not `$.<field>`.** Agent output nests under structuredOutputs. Agent-to-agent and code-to-code use top-level `$.<field>`; only code-reading-agent needs the structuredOutputs prefix. Symptom when wrong: the code node gets None/empty or the whole wrapper object (a body check like startswith("{") then misfires). Belt-and-suspenders: also have the code unwrap dict inputs.

**3. Post-async nodes cannot resolve `$.<field>` from the TRIGGER.** After the first async node, pinned inputRefs to the trigger (`sourceNodeId = trigger`) resolve to nothing and the node fails (isAsync=true, empty). Fix: carry every needed trigger field on an early SPINE node (here node 5a `wfn_0tiehcioJrFRnJc9Riq`) and have deep nodes read from THAT node, not the trigger. A regular node's output propagates run-wide; the trigger payload does not.

**4. `clay_function` tool nodes (shared Functions invoked in a workflow) are the async-callback failure point.** They write to the function's own table and await an async write-back to origin.asyncCallbackId; that callback doesn't reliably complete inside workflow runs, so downstream HOLD/gate nodes sit pending forever or fail. Simple/fast functions sometimes complete; AI-driven ones (fn_draft_critic) and terminal joins do not. THE FIX that worked: convert them to INLINE nodes — malformed-guard fn -> inline code, figure-critic fn -> inline agent (port the function's prompt verbatim), send-ready fn -> inline code computing the gate. The shared Function stays intact for other motions; this workflow just stops calling it. Inline agent/code nodes complete reliably; async function/tool nodes are the thing to avoid inside a workflow that must complete.

**5. nodeType cannot change in place** — to convert tool->agent or tool->code, `edit_node delete=true` then create a new node (omit nodeId), then rewire edges by updating the downstream node's incomingEdges + inputSchema sourceNodeId. A conditional node's inputSchema LAGS after an edit — re-send inputSchema a second time and re-`read` to confirm it points at the new source (else validate errors `inputref_invalid_source_node`).

**6. Terminal output node needs explicit inputSchema.** The Assemble node had inputSchema=null and returned blank msg1-5; wire each output field to a real source.

**7. THE REAL CAUSE of the blank WF Msg columns (proven by reading a completed run's per-node inputs/outputs via `clay workflows runs steps <wf> <runId>`): a CODE node's `context.get_input(key)` reads `key` from the RAW merged output of its incoming nodes — the inputSchema property NAMES and `sourcePath` do NOT reshape the payload for code nodes.** A capture node declared inputSchema `body <- VoiceFix $.structuredOutputs.revised_body` but its code got `{stepsTaken, structuredOutputs:{...}}` (VoiceFix's raw output) and `get_input("body")` returned empty -> blank propagated everywhere. (The old compose-records "worked" only because their schema names happened to match 5a's real top-level keys like `why_now`; it was never the sourcePath doing the work.) So to read an AGENT node's field from a code node: `so = context.get_input("structuredOutputs"); so.get("revised_body")` — read the RAW key, then navigate. NOT `get_input("revised_body")`.

Second trap: a code node's own output ALSO carries an empty `structuredOutputs: {}`. So if a capture (empty structuredOutputs) and a Voice Fix agent (real structuredOutputs) BOTH feed one node, the top-level `structuredOutputs` key COLLIDES and can resolve to the empty one. Fixes: (a) give every code node UNIQUE output field names (msg1_*, msg2_* ... never a shared `structuredOutputs` read), (b) when a node has multiple incoming, read a specific source via `context.get_input("_branchOutputs")[<sourceNodeId>][<key>]` (Clay nests each branch's full output under `_branchOutputs` keyed by node id) with a top-level fallback.

**8. MULTI-INCOMING JOIN NODES DON'T FIRE in this workflow — they sit `pending` forever even after ALL parents complete.** Confirmed twice by reading run steps: a 5-incoming Assemble stayed pending with all 5 parents done; 2-incoming "threaded" captures each stayed pending with both parents done. The whole run then hangs in `running` forever. So NEVER use a join (fan-in) to collect data. Build a LINEAR spine where every node has exactly ONE incoming edge, and pull cross-branch data via DISTANT `sourceNodeId`/`sourcePath` references in inputSchema (which resolve as long as the referenced node is an ANCESTOR of the reader). Distant refs to a CODE node's top-level field populate `get_input(<schemaName>)` by name (this is how the old compose-records read node 5a across many hops, and how the Assemble terminal reads all 5 capture nodes). Distant refs to an AGENT's `structuredOutputs` do NOT work (rule 7) — capture agent output into a code node immediately, then reference the code node distantly.

**9. THE BIGGEST TRAP: a `clay_table` trigger (the "Invoke Workflow" column) PINS a workflow SNAPSHOT and does NOT follow your edits.** `clay workflows runs test` runs the live DRAFT, but the table column fires a trigger whose `snapshotId` was frozen when the column was created. So you can fix + test the draft green all day while the column keeps running the OLD graph and failing on nodes you already deleted (symptom: column run errors like `no completed step found for source node <deleted-node>` / references HOLD/critic nodes that no longer exist in the draft). Diagnose: `clay workflows runs list <wf>` shows each run's `workflowSnapshot.id` and `trigger.id` — if the run's snapshot is old, that's it. FIX (do this in-session, no UI needed): grab the `trigger.id` from `runs list`, then `mcp surfaces_edit_trigger` with `resourceId=<trigger.id>`, `trigger.snapshotId=<concrete newest snapshot id>`. IMPORTANT: a `clay_table` trigger will NOT dispatch with `snapshotId:"latest"` — the cell shows "failed to run" with no reason. You MUST pin a CONCRETE snapshot id (from `snapshots list`, newest first). Tradeoff: it no longer auto-follows edits, so RE-PIN to the new snapshot after every structural workflow change, as the last step before the user runs the column. CONFIRMED WORKING in production Jul 20 once pinned to a concrete snapshot. Verify with `surfaces_read` (trigger). The "clay_table triggers are created only from the UI" note only blocks CREATE, not this snapshotId UPDATE. ALWAYS set a table trigger to `snapshotId:"latest"` after any structural workflow edit. (Stars trigger id: 6c999a95-8ec4-4c5f-8b01-677425d551dc, table t_0thtm73HHxyiupTuepK, field f_0tihfhlVMZAjmcWgejt.)

WORKING SHAPE (Stars 5-touch, FINAL): purely linear single-incoming chain MsgE1->VoiceFixE1->CaptureE1->MsgE2->VoiceFixE2->CaptureE2->...->VoiceFixE5->CaptureE5->Assemble. Each CaptureEn is single-incoming off its VoiceFixEn (immediate raw read `get_input("structuredOutputs")["revised_body"]`), and is inserted INTO the spine (MsgE(n+1) is fed by CaptureEn, not VoiceFixEn) so all captures are ancestors of the terminal. Assemble is single-incoming off CaptureE5 and reads msg1..msg5 from the five capture code nodes via distant sourceNodeId refs. No fan-in anywhere.

OLD (superseded) SHAPE that stalled: Voice Fix E1-E5 each -> its own single-incoming Capture En code node (`so=get_input("structuredOutputs"); return {msgN_subject: so.revised_subject, msgN_body: so.revised_body}`), and ONE Assemble terminal with all 5 captures as incoming, reading the 5 uniquely-named msg fields (with `_branchOutputs` fallback). No threading needed; uniquely-named fields don't collide, and all-incoming = all-upstream = zero validate warnings.

Applied to all 5 touches; workflow validates clean and (E1 proven) completes end-to-end producing msg1-5 subject/body. See [[invoke-workflow-trigger-inputschema-jul20]], [[stars-5touch-concurrency-fix-jul20]], [[voicefix-two-pass-architecture-jul20]].
