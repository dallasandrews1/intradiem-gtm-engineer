Sep 15 2026, Dallas: "there's a better, more dynamic, animated, impressive way to showcase and use as our control tower vs the stale and long-winded version." Rebuilt `Control_Tower.html` (repo root, same `control_tower_state.json` contract) on the current Intradiem kit: forest surface, Roboto/Roboto Mono, inline logo, nine sections (gates rail with pulsing status, the line with a particle canvas where one dot is ten leads and dots park at the send gate, funnel with count-ups, motion rings, send-capacity lanes, signals, blockers, swarm job grid with heartbeat, source freshness table), Present mode (P key or button, arrows, Esc). Live: **https://gtm-control-tower-dn8.pages.dev** (Dallas's Pages project `gtm-control-tower`, noindex, cache-control no-cache). Cloudflare gave the project the `-dn8` subdomain because the bare `gtm-control-tower.pages.dev` belongs to a different account (a public CRM-audit demo); `pages project create gtm-control-tower` says "already exists" because Dallas's project has that name. A `gtm-tower` project created by mistake on Sep 15 was deleted the same hour.

**Assembler changes (`build_control_tower.py`, identical copy in main and the worktree):** `read_swarm()` from the newest swarm-health log; `read_deliverability_watch()` per-mailbox bounce from the newest deliverability-watch log (replaces the seeded EXAMPLE domains); headline derived from the live campaign read ("1,897 loaded, 190 launched, 1,707 waiting", no more "0 sends by design"); degraded-export fallback: when the newest scorecard log lists EXPORT ERROR campaigns or a campaign's leads drop to zero after a non-zero day, the row, STALLED and capacity lines are carried from the last clean log and `live_campaigns.degraded.carried_from` says so (the page shows a CARRIED chip and states it in the subtitle). First hit the morning it was built: Sep 15's export failed on all 39 campaigns.

**Refresh loop:** `automation/run_control_tower.sh` builds, copies index + state into `control-tower/deploy/` (with `_headers` noindex and a 404), and pushes with wrangler when `automation/config/control_tower_publish.json` has `deploy: true` (it does). The loaded launchd job `com.dallasandrews.gtm.controltower` runs it at 7:30 daily from the main checkout, before the 7:50 rundown, so the link is never older than a day. Logs are gitignored, so the assembler only has real data when run from main.

**Sep 14 predecessor:** `build_control_tower_page.py` (chained in `run_daily_rundown.sh` with `--deploy`) rendered the first tower page to the same project, but it wrote to the Desktop, which launchd cannot, so it failed every run. That step is commented out of the rundown wrapper; `run_control_tower.sh` (7:30 job) is the only deploy path now.

Section 5 shows every mailbox in `send_capacity.json`; Jack's second-domain mailbox was added there Sep 15 with Nathan's ramp (switch date UNVERIFIED for Jack).
