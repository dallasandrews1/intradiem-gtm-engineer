Jul 20 2026: Standing rule for ALL social-proof / value examples used in prospect copy (MessageGen product_angle menus, sequences, decks): the line must attribute the achievement TO INTRADIEM AS THE CAUSE, e.g. "Humana's seen a 7X ROI automating this work **with us**" / "**using our automation**" — never a bare figure ("Humana saw 7X ROI") with no causal tie.

**Why:** the whole point of citing a peer result is to make the prospect read it as "they did this WITH Intradiem, so Intradiem would do it for us too." A bare stat doesn't carry that; the causal attribution is the persuasion.

**How to apply:** write every customer proof line with an explicit causal tie, Dallas's preferred phrasing is "**working with us**" (or "after bringing us in"). Do NOT use "using our automation" — Dallas rejects it because "automation" downplays the work/product built. When the thing itself must be named, say "**dynamic workforce orchestration**" (the DWO category), NEVER "automation" (undersells) and NEVER "products" (salesy, delete-email red flag). Use "us / our" not a second literal "Intradiem" (the figure critic FAILs >1 Intradiem mention).

**Key distinction (surfaced Jul 20):** a customer-success proof (we caused it, e.g. Humana) is NOT the same as a third-party STAKES figure (cost of inaction, e.g. the UnitedHealthcare $190M secret-shopper court figure). Stakes figures can't be attributed to us (we didn't cause them) and must NOT go in the customer-proof menu; they're a separate problem-framing / cost-of-inaction tool. Keep the two buckets distinct so a stakes number is never dressed up as an us-caused win. See [[voicefix-two-pass-architecture-jul20]] and the Intradiem Value Repository Humana quotables section.
