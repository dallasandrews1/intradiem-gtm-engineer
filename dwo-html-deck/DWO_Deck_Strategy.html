The call

Rebuild natively, don't export

A PowerPoint-to-HTML export freezes pixels: every future edit means re-exporting, brand drift creeps in per-slide, and there's no place for a presenter layer. The stronger move is a native rebuild on three separated layers, so each requirement is solved structurally instead of patched.

Content layer

One labeled block

Every word on every slide lives in one block at the top of the file, in reading order. Changing the deck means changing text, nothing else. This is what makes "constantly evolving" cheap.

Layout layer

Brand-locked layouts

The layouts render the content. Fonts, colors, spacing, and the logo mark are tokens from the current Intradiem kit, so an edit can't push a slide off-brand.

Presenter layer

Talk track, never shown

The notes ride in the same file but only render in presenter surfaces. What a customer sees on a shared screen is always just the slide.

One more deliberate choice: the deck is a single self-contained file with the brand fonts embedded. No install, no internet required, no dependencies. It opens in any browser on any laptop, which is exactly the bar PowerPoint sets for reps presenting in a room with bad wifi.

The evolving-deck answer

Three lanes to update it

Lane 1 · Words
Anyone comfortable in a text editor, minutes. The top of the file is a labeled content block with every slide's text in reading order. Change the words, save, refresh the browser. Layouts and brand styling are locked and can't break. If a stray quote mark ever breaks the block, the deck simply won't load until it's fixed, and SharePoint version history rolls it back.
Lane 2 · Slides
Claude, minutes. New slide, reordered story, a different layout, a notes-stripped prospect copy: paste the file into Claude, describe the change, and ask for the brand skill to be applied. Because content and layout are separated, Claude edits reliably here, which is the adjustment lever for the brand drift the team has seen.
Lane 3 · Versions
The file is its own record. A version log sits in the file header. Convention: track the PPT master's numbering, so the HTML for Story-V03 is v3.x. The file lives in the Design Asset Library beside the PPT and travels fine as an attachment; it works with no connection.
The QBR peek

Ninety seconds at the Sales QBR

Tom flagged a possible peek at the Sales QBR and it's ready now. The demo that lands:

  1. Open the file, F for fullscreen: the cover reads instantly as Intradiem, no PowerPoint anywhere.
  2. Arrow through the biggest-bet open into the execution-gap slide, so the room sees real content, not a mockup.
  3. Press P: the presenter window appears with the talk track, timer, and next-slide preview. This is the moment reps care about. Let a rep drive it.
  4. Close with the update story: the words live in one block; marketing edits text or asks Claude, and the brand can't drift.
